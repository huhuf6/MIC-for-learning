# Agent 项目 43 问 QA（底层原理版）

## 使用方式
- 面试前先看每题的“核心点”，再用“工程回答模板”组织语言。
- 若被追问，优先讲：目标指标、系统边界、失败模式、评估与回滚。

## 1. 为什么做 Agent 项目？
**核心点**：把“单次问答”升级为“可执行任务系统”。  
**回答**：因为业务问题通常是多步骤、跨工具、跨数据源的。Agent 能把规划、调用工具、验证结果、重试回滚串成闭环，提升自动化率与交付速度。价值不在“聊天”，而在“把任务做完且可审计”。

## 2. 了解过市面上有哪些 Agent 吗？
**核心点**：按产品形态分类，不要只背名字。  
**回答**：可分三类：  
- 通用生产力：如 AI 助手/办公 Agent，偏工作流自动化。  
- 开发类：代码生成、重构、测试、PR 审查 Agent。  
- 企业流程类：客服、工单、报表、知识运营 Agent。  
技术上都围绕“模型+工具+记忆+编排+评估”。

## 3. 讲下 Agent 项目
**核心点**：用“场景-架构-指标”三段式。  
**回答**：先讲业务目标（如工单自动处理），再讲架构（Planner/Tool Router/Executor/RAG/Memory/Guardrail），最后讲效果（成功率、时延、人工接管率、成本下降）。

## 4. Agent 项目开发框架
**核心点**：框架是“编排层”，不是能力本身。  
**回答**：常见框架提供状态机、工具注册、记忆管理、流式输出、回调追踪。选型看三点：可观测性、可控性（可中断/重试）、与现有系统集成成本。

## 5. 介绍一些 AI 大模型
**核心点**：按能力与部署条件对比。  
**回答**：从通用能力（推理、代码、多语种）、上下文长度、工具调用能力、部署方式（云/API/私有化）、推理成本五维评估，避免只比较参数规模。

## 6. RAG 系统流程
**核心点**：召回与生成解耦。  
**回答**：数据清洗切分 -> 向量化建索引 -> Query 改写 -> 检索召回 -> 重排过滤 -> 上下文构造 -> 生成回答 -> 引用与评估。关键是“检索质量决定上限”。

## 7. MCP 和 Function Calling
**核心点**：协议层 vs 模型能力层。  
**回答**：Function Calling 是模型输出结构化工具调用意图；MCP 是标准化“模型如何连接外部工具/资源”的协议生态。前者解决“调用什么”，后者解决“怎么统一接入”。

## 8. 如何写好的 Prompt
**核心点**：约束 + 上下文 + 输出格式。  
**回答**：明确角色、任务边界、成功标准、禁止项、输入变量、输出 schema 和示例。对复杂任务用“分步提示 + 自检清单 + 失败回退策略”。

## 9. 多轮对话的实现方案
**核心点**：上下文管理，不是无限拼接。  
**回答**：短期记忆存最近轮次，长期记忆存事实摘要；通过窗口裁剪、对话摘要、关键信息槽位化，控制 token 与漂移。对关键状态使用结构化存储而非自然语言。

## 10. Agent 项目背景
**核心点**：背景要可量化。  
**回答**：典型背景是人工流程长、重复操作多、知识分散、错误率高。目标是提高自动化率与一致性，并把隐性经验沉淀为可复用策略。

## 11. LLM 产生幻觉的原因及解决方案
**核心点**：生成模型“像真”不等于“真”。  
**回答**：原因包括训练数据噪声、知识过期、检索缺失、任务约束不足、解码随机性。解决：RAG+引用、工具校验、结构化输出校验、拒答策略、离线评测与在线监控。

## 12. MCP 协议的核心内容
**核心点**：标准化模型上下文与工具能力暴露。  
**回答**：核心是统一的能力声明、调用协议、资源访问与会话上下文传递，让模型客户端可插拔接入多种工具服务，降低“每个工具一套私有接口”的成本。

## 13. 推理模式的差异化设计
**核心点**：按任务复杂度分级推理。  
**回答**：简单问答走快速模式；复杂任务走“规划-执行-验证”；高风险场景加双模型复核。通过策略路由在准确率、时延、成本之间动态平衡。

## 14. RAG 检索优化策略
**核心点**：召回率和精确率共同优化。  
**回答**：改进切分粒度、混合检索（向量+关键词）、Query Rewrite、多路召回、Cross-Encoder 重排、元数据过滤、去重与新鲜度加权。

## 15. 特定推理模型不支持 MCP 的技术原因
**核心点**：接口与行为契约不匹配。  
**回答**：可能缺少稳定工具调用 schema、流式控制能力不足、上下文状态管理不完整，或厂商策略未开放。不是“模型聪明度”问题，而是“协议适配能力”问题。

## 16. Agent 推理模式
**核心点**：ReAct/Plan-Execute/Reflect 等模式的取舍。  
**回答**：ReAct 交互灵活但可能冗长；Plan-Execute 可控性高；Reflect 适合高精度但耗时。生产中常做混合：先规划，再局部反思纠错。

## 17. 跨模块错误追踪的 Agent 知识库构建方案
**核心点**：错误链路要结构化。  
**回答**：采集日志、调用链、代码映射、历史事故单，构建“症状-根因-修复”图谱；检索时先按模块与版本过滤，再做语义召回和证据排序。

## 18. 多 Agent 执行策略的智能选择和切换机制设计
**核心点**：策略路由器 + 健康监控 + 回退。  
**回答**：基于任务类型、实时负载、历史成功率选择主 Agent；执行中监控超时/失败信号触发切换；保留人工接管与幂等重试机制。

## 19. 简历关键词提取的技术实现
**核心点**：规则与模型结合。  
**回答**：先做 OCR/结构化解析，再用 NER+词典标准化提取技能、年限、行业词；最后去歧义并映射到统一 taxonomy，输出可检索标签。

## 20. RAG 评估方案
**核心点**：检索评估与生成评估分开做。  
**回答**：检索看 Recall@K、MRR、nDCG；生成看事实一致性、引用覆盖率、答案完整性、幻觉率；再看端到端任务成功率与人工评分一致性。

## 21. SSE 的局限性
**核心点**：单向流、连接管理弱。  
**回答**：SSE 简单但仅服务端单向推送，不适合双向高频交互；在复杂网络下重连、粘包、代理超时处理较麻烦；大规模并发时连接资源占用明显。

## 22. 举例复杂任务下执行流程
**核心点**：给出可落地步骤。  
**回答**：以“生成周报+异常分析”为例：任务拆解 -> 拉取多系统数据 -> 清洗聚合 -> 异常检测 -> 证据检索 -> 生成报告 -> 人工确认 -> 入库归档。

## 23. MCP 通信方式
**核心点**：客户端-服务端标准交互。  
**回答**：模型客户端通过协议与 MCP Server 建立会话，发现能力、提交调用请求、接收结构化结果与资源内容；重点是统一 message schema 与会话上下文。

## 24. 项目中 AI 贡献的代码占比
**核心点**：不要只报比例，要说质量闭环。  
**回答**：可回答“AI 辅助生成 X%，核心设计与验收由人负责”。强调静态检查、单测覆盖、Code Review、回归测试后才入主干。

## 25. Prompt 工程的实践经验
**核心点**：模板化 + 版本化 + A/B。  
**回答**：做 Prompt 模板库，参数化输入，版本管理和灰度发布；配自动评测集做 A/B，按准确率/拒答率/成本持续迭代。

## 26. 基于代码构建知识库的 Agent 设计
**核心点**：语义切片要保留结构关系。  
**回答**：按文件-类-函数-调用关系建索引，结合 AST 与符号表；检索时先走路径过滤再语义召回，输出时附源码片段与定位信息。

## 27. A2A 协议
**核心点**：Agent 与 Agent 的协作协议。  
**回答**：A2A 面向多智能体互联，定义能力发现、任务委派、状态同步与结果回传，让不同 Agent 可组合成分布式执行网络。

## 28. 长文本生成的技术方案
**核心点**：分段生成 + 约束一致性。  
**回答**：先做大纲规划，再按章节生成，维护全局记忆与术语表；每段后做一致性检查和引用校验，最后统一润色与重复消解。

## 29. Agent skills
**核心点**：可复用的任务能力包。  
**回答**：Skill 通常包含触发条件、输入输出 schema、执行步骤、工具绑定与失败回退，目标是把经验沉淀成可组合组件。

## 30. 演示 Agent 项目实现细节
**核心点**：重点展示“可控与可观测”。  
**回答**：演示任务路由、工具调用日志、token/时延监控、失败重试、人工接管、结果追溯链路，而非只展示最终回答。

## 31. 了解其他 Agent 范式吗
**核心点**：单 Agent 与多 Agent 的范式对比。  
**回答**：有 ReAct、Plan-and-Execute、Tree/Graph Search、Supervisor-Worker、多 Agent 竞赛/协商等。选型看任务分解难度与协作成本。

## 32. 模型预热机制
**核心点**：降低冷启动尾延迟。  
**回答**：通过常驻实例、权重预加载、KV cache 预填、热点 prompt 预编译、连接池保活，把首 token 延迟稳定在 SLA 内。

## 33. NL2SQL 场景下的 SQL 安全防护
**核心点**：最小权限 + 语法校验 + 沙箱执行。  
**回答**：只读账号、库表白名单、AST 级 SQL 审查、敏感字段脱敏、LIMIT 强制注入、超时熔断、审计日志全量留存。

## 34. 复杂任务执行准确率提升的评估方法
**核心点**：过程指标 + 结果指标双评估。  
**回答**：拆成计划质量、工具成功率、检索命中率、最终任务完成率；通过错误归因矩阵定位瓶颈，再做针对性优化。

## 35. AI 辅助 IDE 开发工具
**核心点**：能力边界与落地方式。  
**回答**：常见能力有补全、解释、重构建议、测试生成、代码审查。落地时要配合私有代码检索、权限控制与审计。

## 36. RAG 动态知识更新
**核心点**：增量索引与版本一致性。  
**回答**：监听数据变更做增量 embedding，按文档版本维护索引快照；查询时带版本路由，支持灰度切换与回滚。

## 37. MCP 和 skill 区别
**核心点**：一个是“连接标准”，一个是“能力封装”。  
**回答**：MCP 解决系统互联与上下文传递；Skill 是具体任务逻辑封装（Prompt+工具+流程）。Skill 可通过 MCP 暴露，也可本地执行。

## 38. 推理模式的选择机制
**核心点**：策略引擎驱动。  
**回答**：基于任务类型、复杂度、历史成功率、预算与时延要求做路由；策略可规则+学习混合，持续用反馈数据更新。

## 39. 企业内部知识库 RAG 的动态持续更新方案
**核心点**：数据治理优先于模型调优。  
**回答**：建立采集-清洗-权限-索引-评测流水线，结合文档生命周期管理（新增、变更、下线），并做权限感知检索。

## 40. Prompt 设计示例
**核心点**：给可执行模板。  
**回答**：  
```text
角色：你是企业知识库问答助手。
任务：基于给定证据回答问题，不得编造。
输入：{question} {contexts}
规则：若证据不足，返回“信息不足”并列出缺失信息。
输出：JSON {answer, citations, confidence, missing_info}
```

## 41. A2A 与 MCP 区别
**核心点**：对象不同。  
**回答**：A2A 主要是 Agent 之间协作；MCP 主要是模型/客户端与外部工具资源的标准化连接。A2A 关注协同执行，MCP 关注工具接入。

## 42. 多阶段召回策略优化
**核心点**：粗召回快，精排准。  
**回答**：第一阶段多路粗召回（向量/BM25/规则），第二阶段重排打分，第三阶段上下文压缩与去重。用离线标注集迭代各阶段阈值。

## 43. AI 辅助开发的实践经验
**核心点**：把 AI 当“高效初稿器”。  
**回答**：让 AI 负责样板代码、测试草稿、文档与重构建议；人类负责架构决策、边界条件、性能与安全。关键是建立“生成-验证-回归”闭环。

## 高频追问的工程回答模板
1. **目标**：业务指标和SLA是什么。  
2. **方案**：模块划分、关键数据流、失败回退。  
3. **效果**：上线前后指标对比。  
4. **风险**：幻觉、安全、成本、稳定性。  
5. **演进**：下一步优化路线与可量化目标。

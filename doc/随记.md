# linalg 中的 ElementwiseOpFusion,这是一种在tensor/linalg级别的语义融合,融合的是linalg.generic对象
%0 = linalg.generic ins(%arg0) outs(%init0) {
^bb0(%in: f32, %out: f32):
  %a = math.exp %in : f32
  linalg.yield %a : f32
} -> tensor<4x8xf32>

%1 = linalg.generic ins(%0, %arg1) outs(%init1) {
^bb0(%x: f32, %y: f32, %out: f32):
  %b = arith.addf %x, %y : f32
  linalg.yield %b : f32
} -> tensor<4x8xf32>

融合前提:
1. fusedOperand 不能为空
2. producer 和 consumer 都必须是 linalg::GenericOp
3. producer 必须是 tensor semantics，并且这个 operand 必须是 ranked tensor
4. producer 的所有 loops 都必须是 parallel 它必须是纯逐元素并行 producer
5. 当前 fusedOperand 必须是 consumer 的输入 operand
6. consumer 这个 operand 的 indexing map 结果数，要等于 producer loop 数
7. producer 结果的 indexing map 必须可逆，目前要求是 permutation
8. 如果 consumer 有 reduction loop，融合后仍必须保住所有 loop bound 信息

1. DispatchCreation 阶段

源码入口：DispatchCreation/Passes.cpp (line 170)

按 pipeline 顺序，和 encoding 直接相关的 pass 主要有这几个：



createPropagateEncodingsPass


注册位置：Passes.cpp (line 181)

实现：PropagateEncodings.cpp (line 96)

作用：把 iree_encoding.set_encoding 往 producer 方向 bubble up。

核心原理：依赖 EncodingPropagationAttrInterface / EncodingPropagationOpInterface，让 encoding 不只是挂在末端，而是沿可传播的 op 往前走。

典型 IR 形状：
mlir



%1 = tensor.cast %0 ...
%2 = iree_encoding.set_encoding %1 ...



会尽量改成“先传播到 %0 的 producer，再重建 encoding”。





createSetEncodingPass


注册位置：Passes.cpp (line 269)

实现：SetEncoding.cpp (line 402)

作用：给满足 data-tiling 条件的 op 自动插入 iree_encoding.set_encoding / unset_encoding。

核心原理：从 SerializableAttr::getEncodingProperties() 取出 operand/result 应该用什么抽象 encoding，然后包住 linalg op。

一句结论：这是“抽象 encoding 的主要注入点”。

createHoistEncodingOpsPass


注册位置：Passes.cpp (line 276)

实现：HoistEncodingOps.cpp (line 183)

作用：把 set_encoding 往 dispatch 外提，或穿过某些 op（generic/broadcast/bit-extend 等）。

核心原理：识别可安全 bubble 的 producer 链，尽量不要把 encoding op 卡死在 dispatch 里。





createFuseEncodingOpsIntoDispatchRegionsPass


注册位置：Passes.cpp (line 283)

实现：FuseEncodingOpsIntoDispatchRegions.cpp (line 62)

作用：把 dispatch 外的 set/unset_encoding 再和合适的 producer dispatch 融回去。

核心原理：找 producer dispatch 链，要求 region 内 op 类型受限，然后把 encoding op 挪进 dispatch region。

一句结论：前一个 pass 是“往外提”，这个 pass 是“条件允许时再融回更合适的 dispatch”。





createConvertEncodingToFlowPass


注册位置：Passes.cpp (line 286)

实现：ConvertEncodingToFlow.cpp (line 24)

作用：把 iree_encoding.set_encoding / unset_encoding 转成 flow.tensor.encode

典型 IR：
mlir

2. Flow 阶段

源码入口：Flow/Transforms/Passes.cpp (line 123)

严格说，Flow 主 pipeline 里没有独立的 encoding pass。

也就是说，没有类似：


createSpecializeEncodingsPass

createSetEncodingPass


这种专门做 encoding/layout 变换的 Flow pass。

Flow 这一层主要是：


承接 DispatchCreation 已经变成的 flow.tensor.encode

继续做 dispatch/executable 组织

为后续 Stream lowering 保留 encoding 信息


唯一和 encoding 沾边但不是主流程变换的，是 tracing 相关代码会在需要时插 flow.tensor.encode / decode 来打印 row-major 视图，见 InjectDispatchTracing.cpp (line 45)。这个一般不算你问的“encoding相关主 pass”。

Flow 到 Stream 的边界上，真正发生的是：


flow.tensor.encode -> stream.tensor.encode

转换模式在 FlowToStream/Patterns.cpp (line 241)

ConvertToStreamPass 入口在 ConvertToStream.cpp (line 311)


所以一句话：

Flow 阶段自己基本不“做 encoding 优化”，它主要是携带 flow.tensor.encode，然后在 Flow->Stream 边界把它接到 stream.tensor.encode。

# RISC-V ELF psABI：整数调用约定、寄存器保存与栈对齐

本文根据本地克隆的官方 RISC-V ELF psABI 仓库整理：

- 仓库：`rvv/RISC-V_ELF`
- 整理时提交：`3095deae52ae3feecc54b5e185d14eb177e05d04`
- 主要规范原文：[riscv-cc.adoc](../rvv/RISC-V_ELF/riscv-cc.adoc)
- ELF 栈对齐属性：[riscv-elf.adoc](../rvv/RISC-V_ELF/riscv-elf.adoc)

这里讨论的是标准的 **Base Integer Calling Convention**。ILP32 和 LP64 都使用这套基本规则；
ILP32F/D、LP64F/D/Q 则在它的基础上增加硬件浮点调用约定。

## 1. 快速结论

- 整数参数优先使用 `a0-a7`，其中 `a0-a1` 也用于返回值。
- `t0-t6`、`a0-a7`、`ra` 是调用者保存寄存器；函数调用后可以被改写。
- `s0-s11` 是被调用者保存寄存器；被调用函数使用它们时必须先保存，返回前恢复。
- `sp` 必须在函数返回时恢复，并且标准 ABI 要求它在整个函数执行期间保持 16 字节对齐。
- `gp` 和 `tp` 是固定用途寄存器，标准 ABI 程序不应随意修改。
- 栈向低地址增长；函数入口处第一个栈参数位于 `0(sp)`，后续参数位于更高地址。
- 标准 ABI 没有可在 `sp` 以下安全使用的 red zone；不要依赖当前 `sp` 以下数据保持不变。

## 2. XLEN 是什么

`XLEN` 是整数寄存器宽度：

| 架构 | XLEN | 一个整数寄存器的字节数 |
|---|---:|---:|
| RV32 | 32 位 | 4 字节 |
| RV64 | 64 位 | 8 字节 |

规范中的“最多 XLEN 位”表示值可放进一个整数寄存器；“2×XLEN 位”表示需要两个整数寄存器。

## 3. 整数寄存器约定

| 硬件寄存器 | ABI 名称 | 用途 | 跨函数调用保存？ | 保存责任 |
|---|---|---|---|---|
| `x0` | `zero` | 常数 0 | 不适用，不能修改 | 无 |
| `x1` | `ra` | 返回地址 | 否 | 调用者；非叶函数通常要保存自己的 `ra` |
| `x2` | `sp` | 栈指针 | 是 | 被调用函数必须恢复 |
| `x3` | `gp` | 全局指针/平台用途 | 固定，不可分配 | 普通函数不得修改 |
| `x4` | `tp` | 线程指针 | 固定，不可分配 | 普通函数不得修改 |
| `x5-x7` | `t0-t2` | 临时寄存器 | 否 | 调用者 |
| `x8-x9` | `s0-s1` | 被调用者保存寄存器 | 是 | 被调用者 |
| `x10-x17` | `a0-a7` | 参数寄存器 | 否 | 调用者 |
| `x18-x27` | `s2-s11` | 被调用者保存寄存器 | 是 | 被调用者 |
| `x28-x31` | `t3-t6` | 临时寄存器 | 否 | 调用者 |

“保存责任”并不表示每次调用都要保存全部寄存器：

- 调用者只有在调用结束后仍需要某个 `a*`、`t*` 或 `ra` 的旧值时，才需要在调用前保存它。
- 被调用者只有在确实使用某个 `s*` 寄存器时，才需要保存并在返回前恢复它。
- 叶函数不再调用其他函数，因此通常不需要保存 `ra`。

### 3.1 调用者保存示例

```asm
# t0 中的值在 call 之后仍然需要，因此由调用者保存。
addi sp, sp, -16
sd   t0, 8(sp)       # RV64
call other_function
ld   t0, 8(sp)
addi sp, sp, 16
```

也可以把需要跨调用保存的长期值放进 `s0-s11`，但当前函数随后就承担了保存和恢复该
`s*` 寄存器的责任。

### 3.2 被调用者保存示例

```asm
function:
    addi sp, sp, -16
    sd   s1, 8(sp)

    # 函数可以使用 s1，调用者看到的原值必须保持不变。
    mv   s1, a0

    ld   s1, 8(sp)
    addi sp, sp, 16
    ret
```

## 4. 整数参数传递

### 4.1 一个 XLEN 以内的标量

最多 XLEN 位的标量使用一个可用的 `a0-a7`；没有参数寄存器时，按值放到栈上。

```c
long add3(long x, long y, long z);
```

调用时通常为：

```text
x → a0
y → a1
z → a2
```

窄于 XLEN 的整数先按其类型的符号属性扩展到 32 位，再符号扩展到 XLEN。一个需要特别
记忆的结果是：RV64 中即使是 32 位无符号整数，传参时也按规则符号扩展到 64 位；函数应按
原始类型解释其有效低位。

在基础整数调用约定中，窄于 XLEN 的浮点值也使用整数规则传递，扩展到 XLEN 后高位未定义。

### 4.2 2×XLEN 标量

2×XLEN 位标量使用两个参数寄存器：

```text
低 XLEN 位 → 编号较低的参数寄存器
高 XLEN 位 → 编号较高的参数寄存器
```

例如 RV32 传递一个普通 64 位整数：

```text
低 32 位 → a0
高 32 位 → a1
```

如果没有参数寄存器可用，整个值放到栈上；如果只剩一个参数寄存器，低 XLEN 位放入该寄存器，
高 XLEN 位放到栈上。

这个“低位放低编号寄存器”的规则按照数值有效位定义，与机器大端或小端无关。可变参数另有规则，
见后文。

### 4.3 大于 2×XLEN 的标量

大于 2×XLEN 位的标量按引用传递：调用者把对象放在内存中，并把对象地址当作参数传入。

```text
原参数：large_value
实际传递：&large_value
```

规范允许被调用函数修改按引用传入的对象，因此不能假设调用结束后临时副本保持不变。

### 4.4 结构体、联合体和固定长度向量

| 对象大小 | 传递方式 |
|---|---|
| 不超过 XLEN | 一个参数寄存器；没有寄存器时放栈上 |
| 不超过 2×XLEN | 两个参数寄存器；只剩一个时可拆成寄存器和栈 |
| 大于 2×XLEN | 按引用传递，参数替换为对象地址 |

结构体字段按照内存布局装入寄存器。填充位以及对象末尾超出有效大小的位，其值未定义。
带非平凡拷贝构造、析构函数或虚表的 C++ 聚合对象也按引用传递。固定长度向量按聚合对象处理。

### 4.5 超过八个参数

以下 RV64 函数有十个 `long` 参数：

```c
long f(long p0, long p1, long p2, long p3, long p4,
       long p5, long p6, long p7, long p8, long p9);
```

入口位置为：

```text
p0-p7 → a0-a7
p8    → 0(sp)
p9    → 8(sp)
```

这里的 `sp` 是被调用函数刚进入时的栈指针。如果函数先建立了自己的栈帧，参数相对新 `sp`
的偏移会随栈帧大小变化；使用帧指针时可以通过入口栈地址（CFA）稳定地访问它们。

### 4.6 可变参数

基础整数调用约定中，可变参数大体按照普通参数传递，但有两个重要例外：

1. 对齐要求为 2×XLEN、且大小不超过 2×XLEN 的可变参数，必须使用偶数编号开始的参数
   寄存器对，例如 `a0/a1`、`a2/a3`。为满足对齐，某个参数寄存器可能被跳过。
2. 一旦某个可变参数开始放到栈上，之后所有参数也都放到栈上。

可变的 2×XLEN 标量在寄存器对中的排列遵循内存布局顺序，以保证 `va_arg` 在寄存器参数被保存到
内存后仍能正确工作。这一点在大端系统上与普通具名 2×XLEN 标量的有效位顺序不同。

## 5. 返回值

返回值按照“同类型的第一个具名参数”相同的方式分类：

| 返回值 | 返回方式 |
|---|---|
| 不超过 XLEN 的标量 | `a0` |
| 2×XLEN 标量 | `a0/a1` |
| 不超过 2×XLEN 的小聚合对象 | `a0` 或 `a0/a1` |
| 本应按引用传递的大对象 | 调用者分配返回对象，并把地址作为隐含的第一个参数传入 |

对于间接返回的大对象，规范不要求函数返回时 `a0` 仍保存该对象地址，程序不能依赖这一点。

## 6. 栈对齐与栈参数

### 6.1 标准 ABI 规则

标准 RV32I/RV64I ABI 的规则是：

- 栈向低地址增长。
- 函数入口处 `sp` 必须按 128 位，即 **16 字节**边界对齐。
- `sp` 必须在整个函数执行过程中保持 16 字节对齐，而不只是调用指令执行前对齐。
- 第一个栈参数在入口 `0(sp)`，后续参数放在更高地址。
- 栈上传递的对象按照“类型自身对齐与 XLEN 位（XLEN/8 字节）对齐两者中较大者”对齐，
  但不超过栈对齐。
- 函数不得依赖当前 `sp` 以下地址中的数据持续存在，即没有标准 red zone。
- 非标准 ABI 代码调用标准 ABI 函数前必须重新对齐 `sp`。

因此，标准函数通常按 16 的倍数调整栈：

```asm
addi sp, sp, -32     # 正确：仍保持 16 字节对齐
...
addi sp, sp, 32
```

下面这种写法在标准 ABI 中会破坏函数执行期间的对齐：

```asm
addi sp, sp, -8      # RV64 中虽然能放一个寄存器，但不再是 16 字节对齐
```

ELF 属性 `Tag_RISCV_stack_align` 记录目标文件要求的栈对齐字节数。默认值为：

| ABI/架构 | 默认属性值 |
|---|---:|
| RV32I/RV64I | 16 字节 |
| RV32E/ILP32E | 4 字节 |

链接器遇到栈对齐要求不同的目标文件时应报告错误。

### 6.2 帧指针

帧指针是可选的。使用时必须放在 `x8`，也就是 `s0/fp`，因此仍属于被调用者保存寄存器。

标准帧记录由两个指针组成。函数序言完成后，`fp` 指向 CFA，即当前函数入口时的 `sp`：

```text
高地址

fp + 0            = CFA（函数入口 sp）
fp - PTRSZ/8      = 返回地址 ra
fp - 2*PTRSZ/8    = 调用者的旧 fp
其余局部保存值
当前 sp

低地址
```

平台可以允许函数省略帧指针或不维护完整帧链，所以不能仅凭 `s0` 的使用断定一定存在帧记录。

### 6.3 RV64 栈帧示例

下面的函数需要调用 `g`，并让局部值 `keep` 跨越这次调用：

```c
long f(long x, long y) {
    long keep = x + y;
    return g(keep) + keep;
}
```

一种符合 ABI 的 RV64 汇编实现是：

```asm
f:
    addi sp, sp, -32
    sd   ra, 24(sp)       # fp - 8
    sd   s0, 16(sp)       # fp - 16，保存旧帧指针
    sd   s1,  8(sp)
    addi s0, sp, 32       # fp = 入口 sp = CFA

    add  s1, a0, a1      # keep 放入 callee-saved 寄存器
    mv   a0, s1           # g 的第一个参数
    call g                # g 可以改写 a*、t* 和 ra，但必须保留 s1
    add  a0, a0, s1      # g 的返回值位于 a0

    ld   s1,  8(sp)
    ld   s0, 16(sp)
    ld   ra, 24(sp)
    addi sp, sp, 32
    ret
```

这个例子同时体现了：

- 栈帧大小 32 字节，始终满足 16 字节对齐。
- `f` 会再次调用函数，所以保存 `ra`。
- `s0`、`s1` 是被调用者保存寄存器，使用前保存、返回前恢复。
- `a0` 是参数寄存器和返回值寄存器，调用 `g` 后不能保留原值。

## 7. 基础整数 ABI 中的浮点和向量寄存器

在纯整数 ABI（ILP32、LP64）中：

- 即使硬件存在浮点寄存器，也没有浮点寄存器需要跨调用保存；它们可视为临时寄存器。
- 浮点参数按照整数调用约定传递，而不是使用 `fa0-fa7`。
- 标准向量调用约定下，`v0-v31` 均不保存，也不用于传递参数或返回值。

ILP32F/D、LP64F/D/Q 会用硬件浮点调用约定补充这些规则。例如 LP64D 可以通过 `fa0-fa7`
传递不超过 ABI_FLEN=64 的浮点参数，并要求适用宽度内的 `fs0-fs11` 跨调用保存。

## 8. ILP32E 的例外

ILP32E 面向 RV32E，当前规范明确提示它尚不稳定。它与标准整数调用约定的主要差异是：

| 项目 | ILP32E |
|---|---|
| 栈对齐 | 32 位，即 4 字节 |
| 参数寄存器 | `a0-a5`，共 6 个 |
| 被调用者保存寄存器 | `s0-s1` |
| 临时寄存器 | `t0-t2` |
| `x16-x31` | 不参与该调用约定；若硬件存在则视为临时寄存器 |

ILP32E 不能用于要求超过 32 位加载/存储对齐的寄存器扩展，尤其不能与 D 扩展配合使用。

## 9. 编写或审查函数时的检查表

1. 参数是否按 `a0-a7`、栈和多寄存器拆分规则放置？
2. 调用其他函数后仍需要的 `a*`、`t*`、`ra` 是否由调用者保存？
3. 函数使用的 `s0-s11` 是否在序言保存、尾声恢复？
4. 非叶函数是否保存了自己的 `ra`？
5. 每次调整 `sp` 后是否仍保持 16 字节对齐？
6. 返回前 `sp` 是否恢复为入口值？
7. 是否避免修改 `gp` 和 `tp`？
8. 是否错误地把当前 `sp` 以下空间当作 red zone？
9. 大对象的参数和返回值是否按引用传递？
10. 是否区分了基础整数 ABI 与带 F/D/Q 后缀的硬件浮点 ABI？

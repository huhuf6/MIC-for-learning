# LLM 八股文 QA（含 Transformer / RAG / 推理原理）

## A. Transformer 原理

### 1) Transformer 为什么比 RNN 更适合大模型？
因为自注意力可并行计算，长距离依赖路径更短（任意两 token 交互只需一次注意力），训练效率和可扩展性更好。

### 2) Self-Attention 的核心公式是什么？
`Attention(Q,K,V) = softmax(QK^T / sqrt(d_k))V`。  
`QK^T` 表示相关性打分，`sqrt(d_k)` 防止梯度不稳定，softmax 得到权重后加权 `V`。

### 3) 多头注意力的意义？
不同 head 学到不同关系子空间（语法、实体、位置模式等），提升表达能力。单头容易信息瓶颈，多头更鲁棒。

### 4) 为什么需要位置编码？
注意力本身是置换不变的，不感知顺序。位置编码把“第几个 token”注入表示，模型才能学习顺序与距离信息。

### 5) Pre-LN 和 Post-LN 区别？
Pre-LN（层归一化在子层前）训练更稳定、适合深层；Post-LN 在浅层可行但深层更易梯度问题。大模型多用 Pre-LN。

### 6) FFN 层作用是什么？
注意力负责 token 间信息交互，FFN 负责每个 token 的非线性特征变换与通道扩展，是容量的重要来源。

### 7) 训练中的 teacher forcing 是什么？
训练时输入真实前缀预测下一个 token，加速收敛；推理时只能用模型自己历史输出，存在 exposure bias。

### 8) 为什么会有 KV Cache？
自回归生成每步只新增一个 token，缓存历史 `K,V` 可以避免重复计算，显著降低解码阶段时延。

### 9) 长上下文为什么难？
注意力复杂度约 `O(n^2)`，上下文越长显存和计算越高；还会遇到位置外推、信息稀释、检索干扰等问题。

### 10) MoE（混合专家）为何能降成本？
参数总量大但每个 token 只激活部分专家（稀疏激活），在提升容量的同时控制单次计算量。

## B. RAG 原理

### 11) RAG 的本质是什么？
把“参数记忆”与“外部知识”解耦。模型负责理解和生成，知识通过检索实时注入，降低幻觉和知识过期问题。

### 12) 为什么 RAG 先检索再生成？
先缩小证据范围，再让模型在高相关上下文上推理，能显著提升事实性并降低 token 成本。

### 13) Chunk 如何切分最合理？
按语义和结构切（标题/段落/函数级），控制 chunk 大小与重叠，目标是“召回到就足够回答，但不过度冗余”。

### 14) 仅向量检索够吗？
通常不够。生产中常用混合检索（向量 + BM25/关键词），兼顾语义匹配与精确关键词命中。

### 15) 为什么要重排（Rerank）？
第一阶段召回强调覆盖，候选会有噪声；重排模型能更细粒度判断 query-doc 相关性，提升 top-k 质量。

### 16) Query Rewrite 有什么价值？
把口语问题改写成检索友好表达（补同义词、实体标准名、时间约束），显著提升召回率。

### 17) RAG 常见失败模式？
- 召回不到关键证据  
- 召回过多导致上下文污染  
- 证据冲突未消解  
- 权限过滤缺失导致越权

### 18) 如何做 RAG 评估？
分层评估：  
- 检索层：Recall@K、MRR、nDCG  
- 生成层：事实一致性、引用正确率、幻觉率  
- 任务层：端到端完成率、人工满意度

### 19) 企业 RAG 的关键难点？
权限体系、知识更新延迟、数据质量参差、版本一致性、可观测性。难点往往在工程治理，不在单点模型能力。

### 20) RAG 与微调怎么选？
知识更新频繁优先 RAG；风格/格式稳定性要求高可加微调。常见是“RAG + 小规模指令微调”组合。

## C. 推理原理（Inference / Reasoning）

### 21) 采样策略对输出有什么影响？
温度、top-k、top-p 决定探索度。低温更稳定保守，高温更发散。生产场景通常低温并配结构化约束。

### 22) Greedy、Beam、Sampling 怎么选？
- Greedy：快但易局部最优  
- Beam：质量较高但成本大  
- Sampling：多样性好，适合创意/多候选  
实际按任务目标选择，不存在绝对最优。

### 23) 什么是“推理模式”？
同一任务下不同执行策略：直答、分步、工具增强、规划执行、反思复核。目标是在准确率/时延/成本间最优。

### 24) 为什么复杂任务要“规划-执行-验证”？
把大问题拆成可验证小步骤，降低一步错全盘错的概率，并能在中间节点做纠错与回退。

### 25) 工具调用如何提高推理可靠性？
把“计算、检索、执行”交给确定性工具，模型负责决策与解释，可减少数学错误和事实臆造。

### 26) 什么是结构化输出约束？
要求模型按 JSON Schema/函数参数输出，配合解析校验和重试，显著降低生产接口失败率。

### 27) 幻觉在推理阶段怎么抑制？
证据先行（RAG）、可验证中间结果、低温采样、拒答阈值、外部校验器（规则/工具/二次模型）联合。

### 28) 多轮对话中推理漂移的原因？
上下文累积噪声、用户目标变化、摘要失真。解决：状态槽位化、关键事实锁定、周期性重写系统上下文。

### 29) 为什么需要“人类兜底”？
高风险任务（财务、法务、生产变更）要求可控性。人类审批点能阻断模型在低置信下的错误执行。

### 30) 推理系统如何评估上线效果？
离线 benchmark + 在线 A/B。看任务成功率、错误类型分布、平均时延、token 成本、人工接管率和用户反馈。

## D. 面试可直接复述的总括

### 31) 一句话讲 Transformer
Transformer 用自注意力在全局范围建模 token 关系，以并行训练和强扩展性成为 LLM 基础架构。

### 32) 一句话讲 RAG
RAG 通过“先检索证据再生成答案”，把知识更新和模型参数解耦，提升事实性与可维护性。

### 33) 一句话讲推理工程
推理工程的本质是策略路由与可靠执行：在准确率、时延、成本、可控性之间做系统级平衡。

### 34) 一句话讲 Agent
Agent 是把 LLM 从“回答问题”升级为“完成任务”的执行系统，核心是工具、状态、策略、评估和回退。
